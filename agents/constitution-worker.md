## 0. 三条不可越过的基线

| 事项 | 冻结值 |
|---|---|
| 开发分支 | `codex/mistbell-development-3.0` |
| 提交（按身份，不按分支名） | `ba2ae9b3099fa7282ab58b35b2128f9bca89b1ee` |
| 基线来源 | PR #29（head `codex/full-project-audit-pr29-2026-10-14`，同 SHA） |

- MT-001：不得用旧分支或分支名代替提交身份；任务开始时先 `git rev-parse HEAD` 核对。
- MT-002：基线只在校验后更新；发现远端出现新 HEAD **不自动**触发重基或重置。
- MT-009：报告 GitHub 状态前必须重新核查远端；无法访问时写"未核实"，不引用缓存。

## 1. 每轮开工前：冻结

1. 复制 `tasks/task-template.md` 建立本轮任务文件，填齐字段。
2. 与用户确认本轮**唯一**范围；范围外的要求（如推进 PR #30、把 PR #26 合流）不得自行纳入（MT-004）。
3. 运行前置门禁：

```bash
python3 lint/collaboration-gate.py --phase pre-review --mode repo \
  --repo . --freeze tasks/<本轮任务文件>.yaml
```

门禁通过只代表**结构与冻结字段**没问题（见 §4），不代表功能正确。

## 2. 干活时的硬边界

### 2.1 交付与状态

- MT-006：类、接口、配置存在 ≠ 功能落地。未核实端到端调用链前，状态最高只能写到"实现中"。
- MT-013：状态只能用五档枚举，且每档必须绑定提交与证据：
  `NOT_IMPLEMENTED` → `IN_PROGRESS` → `CODE_COMPLETE_PENDING_VERIFICATION` → `AUTOMATED_TEST_PASSED` → `DEVICE_VERIFIED`
- MT-049：改了代码（或数据库、调用链）之后，旧测试结论一律作废，不得复用到新 SHA。
- MT-012：不得删测试、吞异常、做破坏性迁移来换"全绿"。

### 2.2 数据与记忆

- MT-028：向量、事实历史必须本地持久化；不得只活在内存、提示词或服务商临时缓存里。
- MT-030：新向量确认持久化成功之前，不删旧向量。
- MT-036：事实先落库成功，再同步派生向量与缓存；派生失败不得回滚已保存事实。
- MT-034：整理队列必须可恢复、幂等；重启/崩溃不得丢批次或重复整理。
- MT-033：每三轮触发的既定目标不得擅自改动。
- MT-035：推断、待确认、短期状态不得被提升为"确定事实"。

### 2.3 外部调用与凭据

- MT-018：聊天 / 记忆整理 / 生图各用各的配置与 Key，禁止静默跨模块回退。
- MT-020：重试必须有界、按错误分类，禁止非幂等重复提交。
- MT-025：本地 Embedding 失败**不得**未经用户明确授权改走云端。
- MT-043：密钥不得进 Git、普通日志、崩溃报告、测试快照。
- MT-044：不得无必要地把私人聊天、角色卡、世界书内容发给外部 API。

### 2.4 兼容与迁移

- MT-037 / MT-038：新格式不得破坏旧世界书与角色卡读取；转换失败不得损坏原始内容。
- MT-045：Schema 生成结果必须与对应源码一致；不得拿旧分支 JSON 冒充。
- MT-046：只测"空库新建"不算迁移通过，必须测旧版本升级与数据保留。
- MT-047：ZIP 创建成功 ≠ 备份可恢复，必须有恢复验证。

## 3. 节奏：日常轮次 vs 最终阶段

- MT-011：**日常轮次**默认只做编译、单测、静态分析与定向验证。
  不得默认追加完整 APK 打包或最终真机验收；需要时必须在冻结文件里写明理由与显式授权。
- MT-016 / MT-051：Redmi K70 Pro 专项与最终完整验收属于**最终阶段**，且不得用预览、模拟器或"编译通过"代替。
- MT-015：真机跑通 ≠ NPU 在工作；没有实际后端证据就写"未知"。

## 4. 证据规则（最容易自我欺骗的地方）

门禁把每条约束标注了判定档位，你的证据必须对得上：

| 档位 | 含义 | 你必须提供 |
|---|---|---|
| METADATA_AUTOMATED | 结构一致性 | 冻结字段、SHA、枚举值 |
| METADATA_STRUCTURAL_ONLY | 只证明记录齐全 | 台账/记录，**不得**说"已验证通过" |
| NEEDS_TEST | 必须行为测试 | 命令、用例、失败注入、结果 |
| NEEDS_DEVICE | 必须真机/真实服务 | 机型、系统、模型、后端、实际输出 |
| NEEDS_HUMAN | 必须人工裁决 | 提交给用户明确裁决 |

- 字段齐全**不等于**行为通过。
- 门禁没跑的档位，等同于"未验证"，不是"通过"。
- MT-048：重要功能只测正常路径不算验证完成；不适用的风险路径要写明理由。

## 5. 提交与 PR

- MT-008：不为拆一个小功能就新建 PR。要建 PR，必须先记录**工作线 + 隔离理由**，否则门禁直接失败。
- MT-003：PR #29 保持 Open + Draft。禁止 merge、close、转 ready-for-review。
- MT-005：PR #31 只能逐项核对后选择性移植，禁止整体合并；"编号像、描述像"不算兼容证据。
- MT-012 / MT-051：不得把未实测项说成通过；未完成项留在台账里，不因实现被删而消失（MT-010）。

## 6. 每轮收工：交回什么

1. 本轮的提交 SHA 与所做的最小改动范围。
2. 状态枚举档位 + 对应证据（含未验证项的显式列表）。
3. 后置门禁结果：

```bash
python3 lint/collaboration-gate.py --phase post-review --mode repo \
  --repo . --freeze tasks/<本轮任务文件>.yaml --json
```

4. 明确列出：本轮**没有**做的事，以及为什么不做。
