# 记忆检索与索引维护优化：范围与验证

## 量化检索

对共同正比例因子 `scale`，实数数学上 `cos(u, scale*b) = cos(u,b)`。mmap int8
快路径直接读取字节，缓存每条记录的字节范数；查询向量仍是浮点。legacy float32 保留原路径。
浮点反量化有舍入，因此不能承诺新旧分数逐位一致；近阈值或近并列时也不能无条件承诺排名一致。

解码校验 scale 有限、为正且不超过 `Float.MAX_VALUE / 127`。对于极大 scale，额外拒绝
会使反量化溢出的 `-128`，不能把绕过有限值检查称为修复溢出。零方向不返回命中，查询入口拒绝非有限值。

TopK 使用容量为 limit 的堆，堆头为最差命中，最终按 `score 降序、id 升序` 排序。
测试与独立全量排序参考比较，也检查不同 limit 前缀；相同算法自身前缀一致并不是充分的正确性证明。

## 文本缓存与提交

缓存键包括规范路径、进程内写代数、稳定 fileKey、长度、高精度修改时间和创建时间；无法获得稳定身份时不缓存。
保存成功或失败均失效。缓存命中之前必须 `AtomicFile.openRead()`，让 `.bak` 恢复先完成；
打开前后身份变化的读取不缓存，解码结束再次核对身份，不把旧描述符内容挂到新路径身份。
返回列表使用不可修改视图。跨实例共享每路径锁，`update` 的读改写整体受锁保护。

所有外部文件替换仍应与 store 协调；身份校验不是多进程事务或抵御刻意保留元数据的任意原地改写的保证。
聊天后台索引提交现在在同一文本路径锁下核对原始记录并写入向量，排除检查与提交间的 source update。
文本已删除时拒绝旧任务提交，不重新创建旧文本。

## 增量重建与真实批量边界

复用要求 `modelId + dimensions + id + sourceTextSha256` 匹配，保留原时间戳。
复用值拷贝脱离旧映射，再按现有格式持久化。测试覆盖30次 `encode -> decodeMapped -> rebuild`
往返，验证此夹具的字节方向、排名和分数不累积漂移；它不是所有非法/外部生产快照的无损保证。

待嵌入记录按 `passageBatchSize` 调用 `embedPassages`，默认回退单条。
实际 LiteRT-LM 引擎调用 `computeEmbeddingBatch`，并非简单循环单条推理。
但 adapter 会按固定8条再拆分、去重或命中缓存，所以 `MemoryIndexRebuildProgress.embeddingRequests`
只计上层 API 请求，**不是原生推理批次**，不可用于宣称原生调用减少倍数。
原生调用数量应取引擎 `embedding.inference.started` 事件。

模型文件和输入策略身份由 runtime 的 `modelId` 提供；整合分支另补文件 SHA-256、policy 和截断/归一化身份。
身份变化触发一次全量重建，不改二进制 codec 版本。

## 性能证据的限制

此前文档给出桌面 JVM 最好轮次约1.8–2.1倍，不提供可重跑的 benchmark 源码、设备/JVM配置、
预热、分配、GC或置信区间，因此不能当作可复现性能验收结果，更不是手机端承诺。
正确性 JUnit 不是性能测试。后续应提交独立 benchmark，分别测冷/暖范数、冷/暖文件缓存、
包含TopK排序的完整检索，以及增量重建持久化耗时；报告多轮分布并在真实设备复测。
本次审查没有重新测量或背书旧性能倍数。

## 合成近邻保持，不是语义召回

`VectorSearchRecallQualityTest` 只比较量化前后**合成向量近邻**：20簇×20条、768维、100次查询。
簇内噪声现在为 `0.55/sqrt(dimensions)`，不再让每维σ=.55淹没已归一化簇中心。
真值使用完整余弦而非仅依赖float归一化后的点积；得分误差对同一命中ID比较更有意义。
现有门限是合成存储回归边界（mean recall@5≥.95、rank1≥.99、top1误差<.002），
不证明真实模型或中文记忆的语义召回。旧文档的200次查询与源码100次不符，旧0.994数值不沿用。
重复相同查询分数不变只能证明确定性，不能证明范数缓存实际命中。

## 验证

- JVM：量化与反量化参考比较、独立全排序TopK、稳定并列、零向量、极大scale下-128溢出拒绝。
- JVM：增量复用计数、模型/维度失效、API请求数、删除、30次持久化重建方向/分数保持。
- JVM：合成存储近邻门限；不含真实模型、真实语料或设备速度评估。
- androidTest：跨实例缓存、同长度写、同元数据新inode替换、`.bak`恢复优先、删除后旧提交拒绝、提交与update互斥。
- 本地额外 JVM AtomicFile 测试替身验证了恢复与提交锁，但不能替代 Android instrumentation。
